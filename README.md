# Ozon Tracker — демонстрация с SQL Server

ASP.NET Core 10 + React/TypeScript/Vite. Доступ к Ozon API не требуется: источник данных — **SQL Server**, управление базой — через **SSMS**. Все товары, идентификаторы, цены, продажи и показатели отзывов вымышлены.

## 1. Создать БД в SSMS на Windows

Нужны **SQL Server 2019 или новее** (Express или Developer достаточно) и **SQL Server Management Studio**. SSMS сама по себе не устанавливает сервер БД. Для API нужен .NET SDK 10, для клиента — Node.js 22.12+ или 24.

1. Откройте SSMS и подключитесь к своему экземпляру SQL Server с Windows Authentication. Для Express это часто `localhost\SQLEXPRESS`, для обычного экземпляра — `localhost`. Используйте имя, с которым подключение в SSMS действительно работает.
2. Откройте файл [Database/setup.sql](Database/setup.sql) и выполните **весь файл** клавишей F5. Учётной записи нужны права создания БД; если их нет, попросите администратора создать `OzonTrackerDemo` и выдать права на создание таблиц и заполнение данных в ней.
3. Обновите список Databases. Появится `OzonTrackerDemo`, таблицы `dbo.Products` и `dbo.ProductSnapshots`.
4. В результатах первого запуска будет **12 товаров, 6 отслеживаемых и 360 срезов** — по 30 дней для каждого товара. Есть рост и снижение цен, пополнение склада и товар без остатка.

Создание таблиц и заполнение выполняются в транзакции. Повторный запуск сохраняет существующие товары, их отслеживание и историю, не добавляя повторные срезы. Файл `Data/products.json` больше не используется; он оставлен как старый пример.

## 2. Подключить API к своему SQL Server

В [appsettings.json](appsettings.json) уже задан локальный сервер:

```json
"ConnectionStrings": {
  "OzonTracker": "Server=localhost;Database=OzonTrackerDemo;Integrated Security=True;Encrypt=True;TrustServerCertificate=True"
}
```

Замените **имя сервера** на то, к которому подключаетесь в SSMS. В JSON обратную косую черту нужно удваивать. При Windows Authentication API подключается от имени Windows-пользователя, запустившего `dotnet run`; ему нужен доступ к БД, даже если в SSMS использовалась другая учётная запись.

Можно задать строку без изменения файла, в PowerShell перед запуском API:

```powershell
# Обычный экземпляр SQL Server; для Express укажите Server=localhost\SQLEXPRESS
$env:ConnectionStrings__OzonTracker = 'Server=localhost;Database=OzonTrackerDemo;Integrated Security=True;Encrypt=True;TrustServerCertificate=True'
dotnet restore
dotnet run --launch-profile http
```

Команды выполняйте **из корня репозитория**, где лежит `OzonTracker.Api.csproj`. Переменная окружения имеет приоритет над appsettings. Для SQL Authentication храните пароль через `dotnet user-secrets` или переменную окружения и не коммитьте его. Строка соединения не передаётся в React.

`TrustServerCertificate=True` предназначен для локальной учебной БД с самоподписанным сертификатом. Для удалённого рабочего сервера настройте доверенный сертификат и используйте `TrustServerCertificate=False`. Проект рассчитан на локальную демонстрацию: авторизация пользователей не реализована, не открывайте API с операциями изменения данных в публичный доступ.

## 3. Запустить интерфейс

Откройте **второй терминал** в корне репозитория:

```powershell
cd ClientApp
npm ci
npm run dev
```

Откройте адрес, который Vite показывает в терминале, на порту **5173**. API работает на порту **5080**; клиент использует его по умолчанию. Если порт Vite занят, освободите его: CORS API настроен на порт 5173. Изменение порта API требует также задать `VITE_API_URL` перед запуском Vite.

## 4. Сценарий показа проекта

1. На главной уже есть 6 отслеживаемых товаров с заполненными ценами и остатками.
2. Откройте карточку: график строится по срезам из БД, таблица показывает дату, обычную цену, цену по карте, изменение цены, остаток, накопленные продажи, рейтинг и число отзывов.
3. Посмотрите вкладки «Изменения цен», «Остатки», «Продажи», «Отзывы» и общий журнал «История изменений». Во вкладке отзывов показаны рейтинг и количество; тексты отзывов не моделируются.
4. Нажмите **«Смоделировать изменения»** на главной. Для каждого отслеживаемого товара в БД добавится срез: цена изменится на ±3%, цена по карте составит 94% обычной, остаток уменьшится на 3 или пополнится на 50 при низком запасе, продажи увеличатся на 3 и количество отзывов — на 1. Рейтинг сохраняется. Это управляемая демонстрация.
5. Откройте карточку снова — последняя точка, показатели и журнал обновились. Перезапустите API: изменения сохранятся в SQL Server.
6. В демокаталоге выберите товар и нажмите «Отслеживать». Можно также ввести его ID или ссылку с таким ID. ID: **100000001–100000012**; первоначально свободны **100000007–100000012**. Неизвестный ID даст ошибку, повторное добавление — конфликт.
7. Удалите товар из отслеживания и добавьте снова: история не теряется. Это выключает `IsTracked`, а не удаляет данные из таблиц.
8. Откройте [Database/demo-queries.sql](Database/demo-queries.sql) в SSMS: запросы показывают текущие цены, историю и изменения через `LAG`. Есть пример записи собственной цены прямо в БД.

Кнопка «Обновить список» и таймер в настройках **перечитывают БД**, не генерируют новые данные. Срезы создаются кнопкой моделирования либо SQL-запросом. `Demo:Enabled=false` отключает endpoint моделирования.

## Проверки

```powershell
# Корень репозитория
dotnet build
# При запущенном API и созданной демонстрационной БД:
powershell -File scripts/Smoke-Test.ps1 -AllowDemoChanges
cd ClientApp
npm run build
npm run lint
```

Smoke-тест проверяет чтение БД, каталог, добавление, конфликт, ошибки ввода, моделирование и сохранение истории после снятия/возврата в отслеживание. Он добавляет срез для всех отслеживаемых товаров; запускайте его только на демонстрационной БД. Нужен хотя бы один неотслеживаемый товар в каталоге.

API: `GET /api/products`, `GET /api/products/{id}`, `GET /api/catalog` (неотслеживаемые товары), `POST /api/products` с `{"value":"100000007"}`, `DELETE /api/products/{id}`, `POST /api/demo/simulate`. История находится в `history` каждого товара; текущие показатели берутся из последнего среза. Время хранится как `datetimeoffset`, денежные суммы — как `decimal(18,2)`. Все пользовательские SQL-параметры передаются отдельно от запросов.

Если API возвращает 503: проверьте службу SQL Server, имя экземпляра, доступ текущего Windows-пользователя к БД и выполнение `setup.sql`. При подключении по сети нужны TCP/IP, порт SQL Server и правила брандмауэра. Для облачного Linux-окружения Windows Integrated Security без отдельной настройки не подходит: нужен доступный SQL Server с поддерживаемой аутентификацией; локальный Windows-сервер автоматически в облако не переносится.


## Профиль, подписки и демочат

Если база уже создана, откройте **[Database/profile.sql](Database/profile.sql)** в SSMS, подключившись к `localhost`, и выполните весь файл (F5). Он добавляет `dbo.UserProfiles` и `dbo.ChatMessages`, не меняя ваши товары, фотографии и историю цен. Повторный запуск сохраняет заполненный профиль и чат. Для новой БД достаточно полного `Database/setup.sql`: он включает обе части.

После обновления проекта перезапустите API и Vite. В меню слева и в меню пользователя справа доступны:

- **Мой профиль**: имя в интерфейсе, ФИО, телефон и описание. Сохранённое имя показывается в шапке приложения.
- **Аватарка**: выбор PNG/JPEG/WebP до 5 МБ, предпросмотр, сохранение и удаление. Клиент обрезает фото до квадрата 256×256; API принимает изображения до 2 МБ. Аватар хранится в SQL Server и остаётся после перезапуска.
- **Почта**: демонстрационная привязка, изменение и отвязка адреса. Письма не отправляются, подтверждение владения адресом не выполняется.
- **Free · Basic**: текущие функции товаров, графики, история и профиль.
- **Plus**: возможности Basic и экспорт отслеживаемых товаров в CSV для Excel (кнопка на странице подписок).
- **Pro**: возможности Plus и демочат с ассистентом. Попробуйте «Покажи сводку», «Какие товары подешевели?», «Что с остатками?» или вопрос о продажах.

Тарифы переключаются без оплаты, карты и срока действия. Доступ к чату и CSV проверяется на сервере. При понижении тарифа история чата сохраняется, но до возвращения на Pro она недоступна. Историю можно удалить через подтверждение в чате; интерфейс показывает последние 100 сообщений. Профиль один, общий для локального демозапуска: регистрация и авторизация не реализованы.

Ассистент **не использует нейросеть**: это локальные шаблоны, которые читают настоящие значения из вашей демонстрационной БД. Он не обращается к Ozon и не делает прогнозы. Реальные ключи API не нужны.

API профиля: `GET/PUT /api/profile`, `PUT/DELETE /api/profile/email`, `GET/POST/DELETE /api/profile/avatar` (multipart-поле `file` для загрузки), `PUT /api/profile/subscription` с `{"subscription":"Pro"}`. Чат: `GET/POST/DELETE /api/chat`, отправка `{"text":"Покажи сводку"}`. Экспорт: `GET /api/products/export`.

Проверка функций профиля при запущенном API:

```powershell
powershell -File scripts/Profile-Smoke-Test.ps1 -AllowDemoChanges
```

Тест временно меняет профиль и тариф, проверяет аватар, почту, CSV и ограничение Pro, затем восстанавливает исходные личные данные, аватар и подписку. Если история чата была пустой, тест очищает свои сообщения; существующую историю не удаляет и оставляет тестовую пару сообщений. Запускайте на демонстрационной БД.
