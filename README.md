# Ozon Tracker — SQL Server, личный кабинет и аналитика

ASP.NET Core 10 + React/TypeScript/Vite. Доступ к Ozon API не нужен: товары и рыночные показатели вымышлены, хранятся в SQL Server. Регистрация и вход работают с паролями; привязка контактной почты, подписки и чат остаются демонстрационными.

## Обновление уже существующей БД

1. Обновите проект из ветки **beta**.
2. В SSMS подключитесь к тому же серверу, где находится `OzonTrackerDemo` (в текущей конфигурации — `localhost`). Откройте **[Database/accounts.sql](Database/accounts.sql)** и выполните **весь файл** клавишей F5. Он добавляет таблицы аккаунтов, личного отслеживания и уведомлений, сохраняя старые товары, фотографии, профиль и историю. Повторное выполнение не сбрасывает данные.
3. Перезапустите API и Vite.
4. На странице приложения выберите **«Регистрация»** и создайте аккаунт со своей почтой и паролем от 8 символов. **Первому созданному аккаунту** копируются прежние профиль, аватарка, демоподписка и переписка. Исходные таблицы остаются в БД. Зарегистрируйте свой основной аккаунт до запуска автоматических тестов.

Каждый новый аккаунт получает начальный набор из 6 демотоваров с историей. После этого отслеживание, цены, срезы, избранное, целевые цены, уведомления, профиль, подписка и чат изолированы по пользователю. Демосценарий одного аккаунта не меняет цены другого. Общими остаются описания и фотографии товаров каталога.

## Первый запуск на Windows

Нужны SQL Server 2019+ (Express/Developer достаточно), SSMS, .NET SDK 10 и Node.js 22.12+ или 24. SSMS — программа управления, сам сервер БД должен быть установлен отдельно.

1. Для **новой** БД откройте [Database/setup.sql](Database/setup.sql) в SSMS и выполните весь файл. Он создаёт `OzonTrackerDemo`, 12 товаров, 360 начальных срезов за 30 дней и все таблицы для текущей версии. Права создания БД нужны только при её отсутствии.
2. Проверьте строку в `appsettings.json`. Используйте **то же имя сервера, с которым работает SSMS**:

```json
"ConnectionStrings": {
  "OzonTracker": "Server=localhost;Database=OzonTrackerDemo;Integrated Security=True;Encrypt=True;TrustServerCertificate=True"
}
```

Для Express имя может быть `localhost\\SQLEXPRESS` (в JSON две обратные косые черты), для LocalDB — `(localdb)\\MSSQLLocalDB`. При Windows Authentication API работает от имени Windows-пользователя, запустившего его: этому пользователю нужен доступ к БД.

3. Из корня репозитория:

```powershell
dotnet restore
dotnet run --launch-profile http
```

4. Во втором терминале:

```powershell
cd ClientApp
npm ci
npm run dev
```

Откройте адрес Vite на порту **5173**. API работает на порту **5080**. Клиент и API должны использовать одно имя хоста (например, `localhost`) для корректной работы cookie. Порт 5173 разрешён в CORS с передачей cookie. Другой адрес API задаётся через `VITE_API_URL` перед запуском Vite; при изменении адреса интерфейса обновите список разрешённых CORS origins в `Program.cs`.

Пароли хранятся в виде солёных PBKDF2-хешей ASP.NET Identity, вход — в HttpOnly cookie на 7 дней. Файлы ключей сессий находятся в `.local/keys` и исключены из Git. Сохраняйте их между перезапусками, иначе придётся войти снова; данные аккаунта остаются в SQL Server. Регистрация не отправляет письмо подтверждения. Восстановление забытого пароля не реализовано.

`TrustServerCertificate=True` используется для локальной учебной БД с самоподписанным сертификатом. Для рабочего удалённого сервера нужен доверенный сертификат и `TrustServerCertificate=False`. Для Linux Windows Integrated Security без отдельной настройки не подходит; строку подключения можно переопределить переменной `ConnectionStrings__OzonTracker`. Пароли SQL не сохраняйте в Git.

## Что показать на демонстрации

### Целевая цена и уведомления

Откройте товар, укажите целевую цену ниже текущей и нажмите «Сохранить цель». На главной выберите этот товар в поле сценария и нажмите **«Началась распродажа · −20%»**. Если цена достигнет порога, на колокольчике появится счётчик, а в разделе «Уведомления» — событие со ссылкой на товар. Уведомление фиксирует цену в момент срабатывания.

Если цена уже ниже новой цели, уведомление создаётся сразу. Пока она остаётся ниже того же порога, повторные срезы не дублируют событие. После подъёма выше цели правило снова готово сработать при снижении. Удаление цели отключает правило. Можно прочитать одно уведомление или все сразу.

### Избранное и сравнение

Нажмите сердечко в списке или карточке; фильтр **«Только избранное»** покажет сохранённые товары. Отметьте 2–3 товара флажками и нажмите «Сравнить выбранные». В сравнении доступны отдельные линии товаров, единый выбор показателя, точные значения в подсказке и таблица текущих характеристик. При снятии товара с отслеживания его выбор для сравнения очищается.

### Интерактивные графики

В карточке, «Статистике» и сравнении можно выбирать:

- Обычную цену, цену по карте, остатки, продажи между срезами, рейтинг или количество отзывов.
- 7, 14, 30 дней либо свой период до 366 дней.
- Группировку по дням или неделям и сравнение с предыдущим периодом той же длины.
- Дополнительную линию цены по карте при просмотре обычной цены одного товара.

Наведите на кружок или коснитесь графика: подсказка покажет дату и точные значения текущего и прошлого периодов. График поддерживает фокус и стрелки клавиатуры, а также разворачивание в отдельное окно.

Для дня/недели берётся **последний срез**, не сумма остатков или средняя цена. Недели — последовательные интервалы по 7 дней от выбранного начала. Пропуски остаются пропусками; отсутствующий прошлый период не подменяется текущим. Даты группируются в часовом поясе браузера. Продажи рассчитываются как разница накопленных счётчиков с предыдущим срезом; без начальной точки или при сбросе счётчика значение неизвестно. Минимум и максимум выбранного показателя учитывают все сохранённые срезы в периоде; изменение процента на графике — между первым и последним доступными сгруппированными значениями.

### Демосценарии

Сценарий можно применить ко всем своим отслеживаемым товарам или одному выбранному:

- **Распродажа** — цена ниже на 20%.
- **Товар закончился** — остаток 0, накопленные продажи увеличиваются на прежний остаток.
- **Поступление на склад** — к остатку прибавляется 50 единиц.
- **Смоделировать изменения** — изменение цены на ±3%, продаж и остатков.

Каждая операция дополняет личную историю срезом. «Обновить список» и интервал в настройках только перечитывают БД. Интервал, создание уведомлений и компактный вид таблицы сохраняются отдельно для аккаунта. При выключенных уведомлениях новые срабатывания не создаются; уже полученные остаются в истории. Демосценарии отключаются через `Demo:Enabled=false`.

### Профиль и подписки

Профиль: имя, ФИО, телефон, описание, аватар PNG/JPEG/WebP (до 5 МБ до обработки; клиент обрезает до 256×256). API принимает изображения до 2 МБ. Контактную почту можно «привязать» в деморежиме: это не меняет почту для входа и не отправляет письма.

**Free · Basic** включает товары, целевые цены, уведомления, избранное, сравнение и аналитику. **Plus** добавляет CSV-экспорт для Excel. **Pro** также открывает чат с демоассистентом. Тарифы меняются без карты и оплаты; доступ к CSV и чату проверяется сервером. Понижение тарифа сохраняет переписку, доступ к ней возвращается на Pro.

Ассистент отвечает по локальным шаблонам и данным личного списка. Примеры: «Покажи сводку», «Какие товары подешевели?», «Что с остатками?». Нейросети, внешнего API и прогнозов нет. Показываются последние 100 сообщений; очистка истории требует подтверждения.

## Проверки

```powershell
dotnet build
cd ClientApp
npm run build
npm run lint
cd ..
node --experimental-strip-types --test scripts/chart-data.test.mjs
# При запущенном API и созданной БД:
node --test scripts/account-workflow.test.mjs
powershell -File scripts/Smoke-Test.ps1 -AllowDemoChanges
powershell -File scripts/Profile-Smoke-Test.ps1 -AllowDemoChanges
```

Тесты графика проверяют группировку, пропуски, нулевые остатки, расчёт продаж и границы периодов. Интеграционные тесты создают изолированные тестовые аккаунты, проверяют доступ, сохранение и разделение данных, срабатывание цели и демосценарии. Их аккаунты остаются в демобазе; тестовые пароли не выводятся. Запускайте их на учебной БД после регистрации своего основного аккаунта. Для Node-теста API другой адрес задаётся переменной `TRACKER_TEST_URL`, для PowerShell — параметром `-BaseUrl`.

Для просмотра личных данных в SSMS используйте [Database/demo-queries.sql](Database/demo-queries.sql), указав ID своего аккаунта. Таблицы `Products` и `ProductSnapshots` теперь являются общим исходным каталогом; личные изменения находятся в `AccountProducts` и `AccountSnapshots`. Старые `UserProfiles` и `ChatMessages` сохранены для миграции. `Data/products.json` больше не используется.

Если API возвращает 503, проверьте имя сервера, службу SQL Server, права Windows-пользователя и выполнение `Database/accounts.sql` (или полного `setup.sql` для новой БД). Если нужен повторный вход, проверьте использование `localhost` с обеих сторон и передачу cookie.
